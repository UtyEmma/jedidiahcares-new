# Website data

These PHP files replace the former `resources/js/data/*.json` files. Each file returns an array and is evaluated by Laravel through `CmsSchema::seed('name')`. They can use Laravel helpers and configuration; do not import these files into JavaScript or place them under `public/`.

- `site.php`, `pages.php`, `interface.php` and `policies.php` own static wording and default identity/contact values. CMS settings continue to override brand, contact, social and SEO values; page layouts and copy have no CMS editor.
- `site.php` derives its default SEO base URL from `config('app.url')` (`APP_URL`). **Website Settings → Pages → Site-wide SEO** can explicitly override that canonical website address. No production hostname is assumed for the running website.
- `navigation.php`, `site.php` and `routes.php` use named Laravel routes for internal links. `routes.php` supplies typed page URLs to React. Detail records include `detailUrl`; projects also include `donationUrl`, generated with the current record slug. Change route paths in `config/website.php` / `routes/web.php` rather than duplicating them in React. Query parameters and section anchors can be appended to these URLs.
- Default brand assets use `asset()`, including support for Laravel's `ASSET_URL`. The public content service resolves contextual photographs with `asset()` after loading their seed definitions. Metadata retains complete HTTP/HTTPS/CDN image URLs and resolves relative paths against the canonical base, including installations in a subdirectory.
- `redirects.php` declares historical paths and destination route names. Destinations are resolved when requested, so route caching does not freeze destination URLs.
- The collection arrays remain seed sources, combined with `database/seeders/data/website-content.json`. Seeding preserves CMS edits. Source URLs, seed media IDs and local source-file paths remain unchanged: they document the original source and keep media imports idempotent. Do not replace historical credits or external social accounts with the runtime domain.

Changes to PHP copy/data do not require a JavaScript rebuild. On production servers, refresh OPcache or restart the PHP workers according to the hosting configuration. Rebuild Laravel configuration and route caches after changing configuration or routes (the deployment command does this). Changes to public TypeScript contracts in `resources/js/types/site.ts` and `content.ts` require the usual client/SSR build. Keep returned data serializable; never include secrets, database models or executable closures in public content arrays.
